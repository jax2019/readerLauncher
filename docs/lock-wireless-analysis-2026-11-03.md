# 掌阅锁屏故障与无线待机分析

核查日期：2026-11-03。设备：Neo 3 Ultra，Android 14 / API 34。锁屏部分修复代码并实机验证；Wi-Fi、蓝牙部分只读分析，没有修改无线策略、无线开关或供电上报。

## 锁屏失败：已确认的问题与证据边界

用户确认故障来自阅桌面首页的“锁屏”按钮。当时 Toast 原文未留存，本次没有复现相同的偶发故障，不能确定那次失败究竟由组件停用、瞬时连接异常还是调用异常触发。

检查时控制组件已经安装，包状态为 `enabled=0`（使用清单默认启用状态），不是被停用。原有按钮本次可以正常唤起控制进程并进入 `Dozing`。历史日志中的 `cached idle & background restricted` 是空闲后台进程回收；进程退出不等于组件未启用，也不能单凭该日志认定它导致了当时故障。

源码中可以确认两个缺陷：

1. 首页锁屏完全依赖 `com.ireaderlauncher.powerbridge/.PowerService`。绑定、调用或连接超时任一步骤失败，就只显示 Toast，缺少独立的锁屏方式。
2. `bindService()` 返回 false 时直接提示“尚未安装控制组件”。服务停用或其他绑定失败同样可能走到这里，因此提示不能证明组件确实未安装。

## 修复行为

- 保留掌阅原有控制组件锁屏路径，使用 `KEYCODE_SLEEP`，不改变无线与省电配置。
- 绑定失败时读取真实组件信息，区分未安装、已停用和暂时无法连接；记录失败日志，便于追查后续偶发问题。
- 连接或执行失败时提供“使用系统锁屏”，复用仅声明 `force-lock` 的设备管理接收器。用户允许后可直接锁屏，之后优先使用系统 `DevicePolicyManager.lockNow()`，不再依赖控制组件。
- 掌阅“桌面设置”增加已有的“锁屏授权管理”入口。用户可提前授权或撤销；取消授权不会锁屏，撤销后恢复使用原组件路径。
- 失败回调只在首页前台且设备仍亮屏时显示操作对话框，避免迟到提示打断其他页面。绑定返回 false 时也清理连接注册。

## Wi-Fi、蓝牙没有立即关闭的原因

阅桌面的锁屏操作只负责息屏；锁屏后的无线关闭由原厂 `com.szzy.ireader.systemui` 负责。锁屏成功和关闭无线是两个独立步骤。

核查所用原厂 APK 与设备当前 APK 的 SHA-256 一致。该机型启用了 `features.support.turn.off.wifi.bluetooth.v2=true`，Android 14 对应 `PowerKeyInitializerV34` 与 `V7.f` 的路径：

| 条件 | 原厂行为 |
| --- | --- |
| 允许息屏关闭 Wi-Fi，且未在充电 | 屏保显示时安排 **45 秒后**关闭 Wi-Fi；处理时再次检查条件 |
| 45 秒内唤醒／屏保隐藏 | 取消待执行的 Wi-Fi 关闭任务 |
| 正在充电，或已充满但仍接电 | 跳过 Wi-Fi 和蓝牙关闭 |
| 允许息屏关闭蓝牙，且未在充电 | 立即投递蓝牙关闭任务，实际关闭由系统异步完成 |
| 唤醒，且无线先前由这套逻辑关闭 | 约 2 秒后恢复对应无线开关 |

因此，刚锁屏就检查 Wi-Fi、短时间频繁唤醒，或者接电锁屏，都可能看到无线连接仍然保留。唤醒后再打开设置查看，也可能看到系统已经恢复无线，不能据此认定整个待机期间都没有关闭。

当前只读快照：

| 项目 | 实测值与含义 |
| --- | --- |
| `key_screen_off_turn_off_wifi` | `1`，允许息屏关闭 Wi-Fi |
| `key_screen_off_turn_on_bluetooth` | `1`，实际含义同样是允许息屏关闭蓝牙；不能根据键名中的 `turn_on` 解读为保留开启 |
| 电池上报 | `AC powered=true`、`status=2`，正在充电，符合原厂跳过关闭的条件 |
| Wi-Fi | 已开启且已连接 |
| 蓝牙 | `ON`，连接状态 `STATE_DISCONNECTED` |
| 媒体会话 | 当前没有活跃媒体会话 |

原厂电池页面“休眠时保留 WLAN／蓝牙”的开关显示与上述两个底层值取反，当前都不是“始终保留”的配置。旧版原厂路径另有听书、媒体播放等保留条件，但不能将旧路径直接套用为这台 Android 14 设备的故障原因。

保持无线可能增加待机耗电，但当前证据不能量化增加多少，也不足以认定它是主要耗电来源。此次设备接电，没有进行离电长时间对照。若在离电、持续锁屏超过 45 秒且未唤醒的情况下仍一直联网，才需要进一步追踪原厂任务是否触发、API 是否执行成功，以及是否被其他应用重新开启；本次没有修改代码来强制断网。

## 验证

- 官方 SDK 构建及 APK 签名校验通过。
- `lock_fallback` 实机专项通过：组件停用提示、实际系统授权页面取消、授权后的首页锁屏、重复锁屏及原状态恢复。
- 原有 `lock` 实机专项通过：组件路径真实息屏，重复锁屏不唤醒，屏幕状态恢复。
- 安装策略的 8 项 Python 离线测试通过。
- 原有省电备份文件前后逐字节一致；测试新增的临时锁屏授权已移除，控制服务恢复清单默认状态。
- Gradle 离线构建无法取得本机未缓存的 Android Gradle Plugin 8.7.3，因此未完成 Gradle lint；这不影响已完成的直接 SDK 构建与实机验证。
